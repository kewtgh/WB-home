# Witbacon 官网审计报告

- 审计日期：2026-07-27
- 审计基线：`main` 分支，提交 `a382ad3`（0.9.1）
- 审计范围：英文页、中文页、样式与交互脚本、静态资源、SEO 文件、GitHub Actions
- 验证方式：源码审查、资源与链接扫描、JavaScript 语法检查、桌面/移动视口静态渲染、线上抓取结果核对

## 总体结论

项目视觉基础完整，双语内容结构一致，站内锚点、本地资源和 canonical/hreflang 配置没有发现断链。当前主要问题不在“页面是否能打开”，而在合规、无障碍、长期维护和转化效率：

1. Google Analytics 在用户同意前加载，站点也没有隐私说明或偏好入口。
2. 自动轮播、移动导航、案例翻转卡和返回顶部缺少完整的键盘、状态与读屏支持。
3. 每个页面包含 3 个 `h1`，线上抓取也会读取为 3 个一级标题。
4. 页面内 26 个 `<img>` 全部缺少固有尺寸和加载策略，存在布局偏移与无差别抢占带宽的问题。
5. JavaScript 依赖 jQuery 3.4.1 和 Bootstrap 4.4.1 的脚本部分；站点实际交互很少，可以使用原生脚本，减少旧依赖和约 165 KB 传输。
6. IcoFont 为十余个图标加载约 1.25 MB 的 CSS/字体；favicon 目录也包含大量重复、过时或体积异常的文件。
7. 联系方式只有 `mailto:`，没有帮助客户组织需求的低摩擦转化工具。
8. 双语 HTML 是手工复制结构，缺少自动化质量门禁；站点地图又基于工作区时间戳，CI checkout 后可能产生无意义更新。

## 已确认的良好部分

- `index.html` 与 `zh.html` 都有正确的 `lang`、canonical、hreflang、Open Graph 和 Twitter 元数据。
- 两页没有重复 `id`，所有站内哈希目标和本地引用资源均存在。
- 图片都有 `alt`，案例已声明为匿名案例，内容表述相对克制。
- 页面在 1440px 桌面渲染下结构稳定，品牌、层级、色彩和主要 CTA 清晰。
- JavaScript 通过 `node --check`，仓库工作区在审计开始时干净。
- `robots.txt` 与 `sitemap.xml` 可用，线上英文页能够正常抓取。

## 问题清单

### P0：隐私与信任

#### A-01 Analytics 在同意前加载

两个页面在 `<head>` 中直接加载 Google Tag，并立即执行 `gtag('config')`。用户没有拒绝入口，也没有后续修改偏好的入口。

影响：

- 无法表达“仅必要功能”选择。
- 第三方请求在用户阅读隐私信息前发生。
- 对面向多个地区的企业服务网站来说，会削弱信任与合规可解释性。

建议：

- 默认不加载分析脚本。
- 增加双语隐私页面、同意横幅和页脚偏好入口。
- 只在明确接受分析后动态加载 Google Tag，并把选择保存在本地。

### P1：无障碍与交互

#### A-02 自动轮播缺少控制和状态

轮播每 4.8 秒自动切换，三个指示器使用无文本的 `<li>`，没有暂停按钮、可读标签、当前项状态或 reduced-motion 适配。

建议：

- 使用真实 `<button>` 指示器并提供标签。
- 增加暂停/继续按钮。
- 鼠标悬停、键盘聚焦、页面不可见或系统要求减少动画时暂停。
- 非活动 slide 使用 `aria-hidden`，其中的可聚焦元素退出 Tab 顺序。

#### A-03 移动导航状态不完整

移动导航通过运行时复制桌面导航生成；开关按钮缺少 `aria-label`、`aria-expanded` 和关联目标，Escape 不能关闭，关闭后也不会把焦点还给开关。覆盖层类名 `overly` 还会增加维护歧义。

建议：

- 改为原生 DOM 实现并维护完整状态。
- 支持 Escape、覆盖层关闭、焦点返回和 body 滚动锁定。
- 使用 `aria-current="page"` 表示当前区域。

#### A-04 案例翻转卡语义与可见性不一致

整张 `<div role="button">` 使用 `aria-pressed` 表示内容展开，背面内容仍可能进入读屏顺序；移动端又以 `display:none` 切换正反面。它本质上是“展开详情”，不是开关按钮。

建议：

- 使用卡内真实按钮和 `aria-expanded`/`aria-controls`。
- 正面摘要始终可见，详情以可折叠区域呈现，避免 3D 翻转造成认知和动画负担。

#### A-05 焦点样式、跳转入口与图标语义不足

- 没有 skip link。
- CSS 全局缺少一致的 `:focus-visible`。
- 返回顶部只有图标，没有可访问名称。
- 装饰图标没有统一 `aria-hidden`。

建议：补齐键盘可见焦点、跳转主内容链接、控件名称与装饰图标声明。

### P1：SEO、性能与鲁棒性

#### A-06 每页有 3 个一级标题

三个 carousel slide 都使用 `h1`。本地扫描和线上抓取均确认每页读取到 3 个一级标题。

建议：每页保留首张 slide 的一个 `h1`，其他 slide 使用视觉等价的 `h2`。

#### A-07 图片缺少尺寸、加载策略和可读描述

两页共 26 个 `<img>`：

- 26 个都缺少 `width`/`height`。
- 26 个都缺少 `loading`。
- 案例和中文画廊的 alt 文本仍使用 “left image”“office scene” 等弱描述。

建议：

- 标志和首屏需要的图片使用明确尺寸与 eager/high priority。
- 首屏外图片使用 `loading="lazy"` 和 `decoding="async"`。
- 改善中英文 alt。

#### A-08 静态资源明显过重或冗余

已确认：

- `witbacon-logo.png` 为 2000×375、约 470 KB，但页面显示高度仅 30–34px。
- 三张案例图合计约 820 KB。
- IcoFont 两种字体合计约 1.16 MB，CSS 约 90 KB，只为十余个图标服务。
- `favicon.svg` 和 `safari-pinned-tab.svg` 各约 235 KB，且多个 Apple Touch Icon 是同一图的不同尺寸与 precomposed 重复版本。
- `witbacon-logo.svg` 只是引用 PNG，并不是真正矢量资源。
- `sea group.png` 文件名包含空格，不利于 URL、缓存规则和工具兼容。

建议：

- 以小型 SVG sprite 取代 IcoFont。
- 压缩 logo 和案例图片。
- 删除未引用脚本、字体、伪 SVG 和过时 favicon 变体。
- 把资源名改为稳定的 kebab-case。

#### A-09 外部字体影响可用性与隐私

Google Fonts 是除 Analytics 外的另一个第三方请求，在 Google 服务不可达时还会延迟字体决策。

建议：使用经过设计的系统字体栈，删除外部字体请求。

#### A-10 缺少结构化数据与更完整的分享元数据

站点有基础 OG/Twitter 信息，但没有 `Organization`/`ProfessionalService` JSON-LD，也没有 `og:image:width`、`og:image:height` 和 `og:image:alt`。

建议：为中英文页面加入一致的 JSON-LD 和图片描述。

### P1：架构与交付

#### A-11 双语页面缺少自动化一致性保护

当前两份 HTML 结构接近但完全手工维护，没有 package、测试或 HTML 质量脚本。未来改动很容易只落在一个语言版本。

本项目体量暂不值得引入大型框架或构建系统；更合适的措施是增加零依赖 PowerShell 验证脚本，对两页结构、元数据、资源、标题和图片策略做回归检查。

#### A-12 sitemap 生成不确定

脚本使用 `LastWriteTimeUtc` 生成 `<lastmod>`。CI checkout 会改变工作区时间戳，可能导致 sitemap 与内容实际变更脱节，并产生额外 bot commit。

建议：优先使用对应 HTML 文件最后一次 Git 提交日期，非 Git 环境才回退到文件时间。

#### A-13 缺少项目说明和版本单一来源

仓库没有 README、版本文件或本地验证说明，版本仅存在提交消息中。

建议：增加 `README.md`、`VERSION`、验证脚本和发布检查清单。

### P2：业务转化与内容

#### A-14 联系入口无法帮助客户形成有效 brief

单纯 `mailto:` 很轻，但客户仍需自己组织公司阶段、需求类型、挑战和时间线；这正是页面正文反复建议提供的信息。

建议新增“咨询需求邮件生成器”：

- 选择服务类型、公司阶段和期望时间。
- 填写核心挑战和联系人信息。
- 本地生成结构化邮件并打开用户默认邮件客户端。
- 不把表单数据发送到服务器，并在表单旁明确说明。

#### A-15 页脚年份和治理入口不完整

年份是静态文本，没有隐私、Cookie 偏好或版本信息入口。

建议：年份由脚本更新；加入隐私、Cookie 设置和版本标识。

## 不建议在本轮引入的内容

- 不引入 React/Vue/SSR：当前静态站点体量不足以抵消构建、依赖和部署复杂度。
- 不实现无后端的“伪在线提交”：不能可靠送达，也容易误导用户。
- 不增加聊天机器人或追踪型营销 SDK：与当前信任和性能目标冲突。
- 不承诺真实业务指标、客户成果或响应时效：仓库中没有可验证数据来源。

- 每页恰好一个 `h1`，本地资源、站内锚点和 sitemap 可自动验证。
